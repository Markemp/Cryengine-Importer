# Cryengine Importer v4.0 Upgrade Plan

## Goal
Upgrade the Blender addon to support Blender 5.0+ and the new USD file format from the 2.0 Cryengine Converter. Drop Collada (`.dae`) support entirely since Blender 5.0 removes it.

## Branch Strategy
- **`release/4.0`** — integration branch off `master`, holds all feature branches
- Feature branches merge into `release/4.0`
- `release/4.0` merges to `master` when all features are complete

---

## Key API Findings

### Blender 5.0+ Changes
- **Collada removed**: `bpy.ops.wm.collada_import()` no longer exists (PR #139337)
- **USD import**: `bpy.ops.wm.usd_import()` is the replacement
- **Addon registration**: `bl_info` still works (treated as "legacy"); new extensions system exists but is optional
- **USD import renamed params** (5.0): `import_subdiv` → `import_subdivision`, `attr_import_mode` → `property_import_mode`

### USD Import Key Parameters
```python
bpy.ops.wm.usd_import(
    filepath="...",
    import_skeletons=True,      # Import armatures from UsdSkel
    import_meshes=True,         # Import mesh geometry
    import_materials=True,      # Import materials
    import_usd_preview=True,    # Convert UsdPreviewSurface → Principled BSDF
    import_blendshapes=True,    # Shape keys
    set_frame_range=True,       # Match scene frame range to USD archive
    create_collection=True,     # Add imported objects to a new collection
    import_visible_only=True,   # Skip invisible prims
    scale=1.0,                  # Scale factor
    read_mesh_uvs=True,         # UV coordinates
    read_mesh_colors=True,      # Color attributes
    import_textures_mode='IMPORT_PACK' | 'IMPORT_COPY' | 'IMPORT_NONE',
    prim_path_mask="",          # Filter to specific prims
)
```

### USD File Structure (from converter)
- **Main file** (`adder.usda`): `SkelRoot > Skeleton` + `Mesh` with skin binding + `_materials` scope with `UsdPreviewSurface` shaders (including textures when present)
- **Animation files** (`adder_anim_*.usda`): `SkelRoot > Skeleton` + `SkelAnimation` with per-frame transforms. Has `startTimeCode`/`endTimeCode`/`timeCodesPerSecond`. No mesh.
- **Naming**: `{model source name}_anim_{animation_name}.usda`

### 3. `feature/animation-import` — New Animation Import Pipeline

**Scope:** Import all animations for a mech, pair them to the main armature as Blender Actions, and clean up extra armatures.

**New Module: `animations.py`**

**Core Workflow:**
1. Parse `.chrparams` XML to get animation list (name → `.caf` path mappings)
2. Scan the body directory for `{mech}_anim_*.usda` files
3. For each animation USDA file:
   a. Import via `bpy.ops.wm.usd_import(filepath=anim_file, import_skeletons=True, import_meshes=False)`
   b. Find the newly imported armature
   c. Extract the Action that was created from the `SkelAnimation`
   d. Rename the Action using the file-derived name (e.g. `adder_anim_additive_hit_react_right`)
   e. Assign/link the Action to the main mech armature (verify bone name compatibility)
   f. Delete the imported animation armature (it's a duplicate skeleton)
4. Store all Actions so they're available in the Action Editor / NLA Editor

**Changes:**

- **`animations.py`** (new)
  - `parse_chrparams(chrparams_path)` → returns list of animation entries (name, path)
  - `discover_animation_files(body_dir, mech_name)` → finds `{mech}_anim_*.usda` files on disk
  - `import_animation(anim_file, main_armature)` → imports single animation, transfers Action, cleans up
  - `import_all_animations(body_dir, mech_name, main_armature)` → orchestrates full animation import

- **`Cryengine_Importer.py`**
  - `import_mech()`: Add animation import step after armature + geometry import
  - Add call to `animations.import_all_animations()`

- **`__init__.py`**
  - Add `import_animations` BoolProperty to `MechImporter` (default True)
  - Add `import_animations` BoolProperty to `AssetImporter` (default True)

- **`constants.py`**
  - Add animation-related constants if needed

**Key Technical Challenges:**
- **Bone name matching**: The main armature and animation armatures should have identical bone names since they come from the same skeleton. But we need to verify this — if the USD importer appends `.001` suffixes to avoid name collisions on the second import, the Action's fcurve data paths won't match the main armature's bones.
  - Mitigation: Import each animation file, grab the Action, then delete the armature before importing the next one. This avoids name collisions.
- **Action transfer**: After importing, the animation data will be an Action on the imported armature. We need to reassign it to the main armature. This should work if bone names match, since Actions reference bones by name in their fcurve paths.
- **Scale/orientation**: Verify the animation skeleton has the same rest pose and scale as the main skeleton. If not, we may need transform correction.
- **Performance**: 55 animation files for adder alone. Each import is a full file parse. May want a progress indicator.

**Naming Convention:**
- Blender names Actions from the `SkelAnimation` prim name (e.g. `run_fwd`), NOT the filename
- After each import, rename the Action to the file-derived name: `adder_anim_run_fwd` (filename without `.usda`)
- This keeps Actions unique across multiple mechs in a scene

**Testing:**
- Import hen_brown with animations (simpler model, fewer animations)
  - Test data: `d:\depot\KCD2\objects\characters\animals\hen\hen_brown.usda`
  - Animations: `d:\depot\KCD2\objects\characters\animals\hen\hen_brown_anim_*.usda`
- Import adder with all 55 animations
- Verify each Action appears in the Action Editor
- Verify Actions can be applied to the armature and play back correctly
- Test with multiple models in one scene to confirm no naming conflicts

### 4. `feature/usd-materials` — Material Handling for USD

**Scope:** Determine and implement the material strategy for USD imports.

**Analysis:**
The converter writes `UsdPreviewSurface` shaders into the USDA files. When textures are present, they should be included in the material. Blender's `import_usd_preview=True` parameter converts these to Principled BSDF node networks automatically.

**Proposed Approach:**
- **Default path**: Let Blender's native USD import handle materials (`import_usd_preview=True`). This should work for most cases where the converter writes complete materials with textures.
- **Enhanced path** (optional): Keep the existing `materials.py` pipeline available as an override for users who want Cryengine-specific shader handling (Glass, Illum, MechCockpit, Nodraw).
- **MechImporter specific**: Continue reading `.mtl` files for mech imports where shader type matters (cockpit glass, nodraw areas, etc.)

**Changes:**

- **`materials.py`**
  - Keep existing material creation functions
  - Add option to augment/replace USD-imported materials with `.mtl`-derived materials
  - May need to match USD material names to `.mtl` material names

- **`__init__.py`**
  - Add `material_source` EnumProperty: `USD_NATIVE`, `MTL_FILE`, `HYBRID`
    - `USD_NATIVE`: Use materials from USDA file as-is
    - `MTL_FILE`: Override with `.mtl` pipeline (current behavior)

**Verified:**
- Converter writes full `UsdPreviewSurface` materials with texture file references (diffuse, specular, normal, opacity, decal, RGB mask maps). Blender imports these as Principled BSDF automatically.
- USD material names follow pattern `{model}_mtl_{submaterial}` (e.g. `adder_body_mtl_adder_body`). Need to check if these can be correlated to `.mtl` sub-material names for the hybrid approach.
- For most imports, native USD materials should be sufficient. The `.mtl` override is mainly needed for special shader types (Glass, Nodraw, MechCockpit).

## Pre-Implementation Verification

### Verified (Blender 5.x manual import)

**1. USD Import Object Hierarchy (adder.usda — skeleton + mesh, no textures):**
```
Scene Collection
  └── Collection
        └── root                    (Xform → Empty/container)
              ├── _materials        (Empty — material scope)
              └── Armature          (Empty — SkelRoot container)
                    ├── adder       (Mesh — small reference triangle, parented to Armature)
                    └── Skeleton    (Armature object — the actual bone hierarchy)
```
- `Armature` is an empty (SkelRoot), NOT the armature object
- `Skeleton` is the actual Blender Armature with bones
- The mesh `adder` is parented to the `Armature` empty
- All imports create a `root` container — multiple imports will produce `root`, `root.001`, etc.
  - Converter may be updated to use model name as root instead

**2. Bone Names:** Use underscores (e.g. `Bip01_Pelvis`, `Bip01_L_Thigh`). Same as Collada output since converter already replaced spaces with underscores. Existing bone name constants should work as-is.

**3. Materials (verified with `adr_left_arm_forearm_uac20_bh1.usda` — has textures):**
- Blender creates Principled BSDF materials automatically via `import_usd_preview`
- Material naming: `adder_body_mtl_adder_variant` (matches USD `def Material` name)
- Converter writes full `UsdPreviewSurface` with texture references:
  - Diffuse → `*_dif.dds` (sRGB)
  - Specular → `*_spc.dds` (sRGB)
  - Normal → `*_ddn.dds` (raw)
  - Additional maps: opacity, decal, RGB mask
- Absolute file paths in USDA (e.g. `@d:/depot/mwo/objects/mechs/adder/body/adder_body_dif.dds@`)

**4. Object Discovery Strategy:**
- Cannot rely on fixed names — must find objects by type after import
- After USD import: scan `bpy.context.selected_objects` or diff `bpy.data.objects` before/after
- Armature: find by `obj.type == 'ARMATURE'` among newly imported objects
- The `root` naming collision means we need to track what's new per import

**Implications for Code:**
- `bones.import_armature()`: Must find the `Skeleton` armature by type, not by name `"Armature"`
- Material pipeline: For most assets, Blender's native USD import handles materials well. The `.mtl` override is only needed for Cryengine-specific shader types (Glass, Nodraw, MechCockpit).
- Post-import object assignment: Use selected objects or object count diffing to identify newly imported objects
- Multiple imports in same scene will have `root.001`, `root.002` etc. — need to handle this

### Verified: Animation Import (adder_anim_run_fwd.usda)

**Scene hierarchy after animation import:**
```
Scene Collection
  └── Collection
        └── Armature.001            (Empty — SkelRoot, .001 suffix due to duplicate)
              └── Skeleton.001      (Armature — duplicate skeleton)
                    ├── Animation   (SkelAnimation prim — stick-figure icon in outliner)
                    └── Pose
```

**Action creation:**
- Blender creates a Blender Action automatically from the `SkelAnimation`
- Action name: `run_fwd` (from `def SkelAnimation "run_fwd"` in the USDA, NOT the filename)
- **Naming concern**: Action names come from the SkelAnimation prim name, which is the animation name without the mech prefix. Multiple mechs would collide (all have `run_fwd`). We need to **rename the Action after import** to include the mech prefix (e.g. `adder_anim_run_fwd`) for uniqueness.

**Skeleton compatibility:**
- Verified: the Skeleton `joints` array in the animation file is **identical** to the main model file (73 joints, exact same set)
- The animation file has a second `joints` array inside the `SkelAnimation` definition (for the animated subset)
- Actions will transfer to the main armature without bone name mismatches

**Animation import workflow (confirmed):**
1. Import animation USDA → creates `Armature.001` + `Skeleton.001` + Action `run_fwd`
2. Rename Action from `run_fwd` to `adder_anim_run_fwd` (file-derived name)
3. The Action's fcurve paths reference bone names that match the main skeleton
4. Assign Action to main armature's animation data
5. Delete imported `Armature.001` and `Skeleton.001`
6. Repeat for each animation file (delete before next import to avoid `.002` suffixes)
